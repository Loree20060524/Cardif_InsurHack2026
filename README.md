# 法遵雷達——保險業 AI 監理情報與異動分析平台

掌握監理變動，聚焦法遵重點。

整合官方公告、法規、裁罰與監理新聞，以 Groq GPT-OSS 120B 或本機 Ollama 提供 AI 重點分析、監理問答與管理摘要。

## 主要功能

- **監理資訊**：依資訊類型瀏覽官方資料，搜尋公告與法規；可依建議關注部門、風險程度及重要性篩選。左側類型與進階篩選共用條件，變更後立即套用；顯示目前條件，可逐項移除或清除所有篩選。AI 完成後會同步篩選結果、結果數與目前詳情。
- **資訊分頁**：每頁可顯示 25、50 或 100 筆，支援上一頁、下一頁及選取頁碼；可載入更早的官方資料。
- **AI 分析**：整理重點、可能受影響部門與流程、需要注意的事項及建議做法，附上官方來源連結。
- **管理摘要**：可從資訊詳情按「加入管理摘要」，或在管理摘要頁勾選一筆或多筆資訊後統一產生報告。第一次手動產生後，新增或取消勾選會在停止操作約 1.2 秒後自動更新；跨頁、搜尋及切換類型會保留選取。
- **監理問答助手**：單一輸入框支援直接問法規或描述工作情境，由 Agent 理解問題、必要時追問，從已收錄官方資料找出相關法規，呈現關聯、原文、官方連結及待確認條件。使用者不需選擇模式，後續可接續補充。
- **修正前後對照**：法規詳情預設收合，逐條顯示新增、修正及刪除文字、版本日期和官方來源。異動摘要由程式產生；部門影響與因應建議標示為 AI 推論。
- **來源狀態**：查看各官方來源的更新情況。

公司作業檢查、SOP 上傳及文件比對已移除。平台沒有公司文件上傳入口；舊的文件解析、比對及私有摘要 API 回傳 HTTP 410。工作情境的回答以官方資料為依據，不顯示自建 SOP 或 IT FAQ。

## 啟動

### Groq GPT-OSS 120B

複製 `.env.example` 為 `.env.local`，將 `AI_PROVIDER` 改為 `groq` 並填入 `GROQ_API_KEY`，再執行 `python server.py`。`.env.local` 已排除 Git 及部署上傳，只由 Python 後端讀取。模型預設為 `openai/gpt-oss-120b`，推理程度預設 `low`；可將 `GROQ_REASONING_EFFORT` 設為 `medium` 或 `high`。所有 AI 功能共用所選供應商，保留原文引用檢查。

### 部署至 Vercel

在專案的 Production 與 Preview 環境設定 `AI_PROVIDER=groq`、`GROQ_MODEL=openai/gpt-oss-120b`，將 `GROQ_API_KEY` 設為敏感環境變數。金鑰不放在前端或 `vercel.json`。

```powershell
python scripts/prepare_vercel.py
vercel link --project cardif-insur-hack2026
vercel deploy --prod
```

部署前先在本機更新官方資料並執行準備腳本。腳本只把頁面與 assets 複製到公開目錄，四份官方資料快照放入後端 bundle；不帶入舊模型的 AI 分析快取。`deployment_data/` 僅允許這四份公開來源 JSON 納入 Git，供 Vercel 從 GitHub 建置時使用。更新快照後，將它們與程式一併提交。

Vercel 已連接 `Loree20060524/Cardif_InsurHack2026`，正式部署分支為 `main`。推送 `main` 後會自動建置，成功後更新正式網址；其他分支只產生預覽部署。Vercel 已保存的 Groq 環境變數會繼續使用，本機 `.env.local` 不納入 Git。

Vercel 的讀寫快取放在 `/tmp`，一般瀏覽直接使用已收錄快照，手動更新仍可讀取官方來源。快取不會跨執行個體或重新部署永久保存；新執行個體使用提交的資料快照。若要永久保存雲端更新與 AI 快取，需再接外部資料庫。

`/api/health` 回報目前供應商、模型與金鑰是否設定，不回傳金鑰值。

### 模型與附件

- 本機 AI 使用 Ollama；預設 API 位址為 http://127.0.0.1:11434/api/chat。
- 為降低等待時間，分析預設使用 `think: false`，保留原本的模型、來源內容與輸出欄位；啟動服務後會在背景預載已安裝模型。
- 無法使用本機 AI 時，公開監理資訊可使用原本的規則備援，畫面依實際分析狀態顯示。
- pypdf 用於官方公告的可讀 PDF 附件，不提供使用者文件上傳。

### 分析速度與設定

`OLLAMA_THINK` 可設定為 `false`（預設）、`true`（開啟 thinking）或 `auto`（沿用模型預設）。單筆分析及管理摘要使用同一設定；不同設定的分析快取分開保存。模型在記憶體中的保留時間由 `OLLAMA_KEEP_ALIVE` 控制，預設 `10m`。修改環境變數後需重新啟動服務。

若要恢復模型原本的 thinking 設定：

```powershell
$env:OLLAMA_THINK = "auto"
python server.py
```

新增分析結果的 `generation_timing` 記錄來源讀取、模型載入、輸入處理、文字生成與整體耗時；取用快取時，這些數值描述原分析的生成時間。

詳情頁的「重新分析」會略過既有分析快取、重新呼叫模型；一般瀏覽仍沿用快取。分析進行中不接受同一事件的重複請求，重跑失敗時會標示狀態並保留原結果。

可使用不寫入正式快取的腳本比較速度：

```powershell
python scripts/benchmark_analysis.py --modes default off --output tmp/performance/comparison.json
```

腳本只連接本機已安裝的 Ollama 模型，預設使用目前本機快取的一筆公開裁罰資料。可用 `--event` 指定資訊 ID，`--summary` 檢查管理摘要，或 `--modes configured` 驗證目前設定。速度與分析品質仍須依實際來源抽樣確認；首筆分析另包含模型載入成本。

## 資料與結果

管理摘要自動更新只依實際勾選項目變更觸發，翻頁或搜尋不會自行替換來源。產生期間仍可調整選取，前端同時只保留一個摘要請求，結束後再依最新選取更新；已過時的回覆不會覆蓋畫面。更新期間及失敗時保留上一次摘要並清楚標示，失敗可手動重試，不會自動反覆重跑。清空選取會停止待執行的更新，顯示重新選取提示；首次產生前不會自動呼叫模型。

監理問答第一版使用中文詞片、常用詞對應與 BM25 排序，沿用目前的 Ollama 模型，不需下載向量模型。搜尋範圍包含本機已保存且符合平台相關性條件的公告、裁罰、新聞及法規原文；每部法規原文使用平台保存的最新版本。來源更新後會重建記憶體中的搜尋索引，不會在提問時抓取外部網站。日期篩選使用發布或修正／公布日，不能作為法規生效期間查詢；沒有完整歷史版本時，也不能據此判定過去某日的適用規範。

每項回答必須引用實際搜尋到的段落，後端檢查來源編號與逐字摘錄，未通過的回答會省略。官方事實直接顯示通過檢查的原文摘錄，避免小模型改寫時反轉例外條件；AI 推論另行標示。這項檢查不等於驗證結論正確，仍須核對摘錄是否支持問題或推論。共用流程先由模型理解問題，沒有相關段落時不進行第二階段的法規回答生成，提示資料不足；模型無法使用時會提示重試，不會把規則結果冒充 AI 回答。

監理問答的推論與建議另進行一輪來源支持核對：將結論、原引用及來源上下文交給模型，區分原文支持、相反、依據不足。程式先對原文片段編號，模型回覆支持的片段編號，後端再還原同一准許來源內的原句，避免要求模型再次抄寫引文。缺漏、重複、無效核對回覆、超過核對範圍或模型失敗時，都不發布未確認的結論，保留原文並提示省略原因。另以程式檢查阿拉伯數字金額及可辨識完整列舉的裁罰加總。這是保守篩選機制，模型仍可能誤判支持關係，不能作為法律適用保證或準確率宣稱。

管理摘要的標題、主摘要、風險判讀、優先關注理由、建議及趨勢也使用同一核對流程，全部選取來源保持不變。未充分支持的欄位會省略或改為資料不足，畫面可展開核對的原文。新快取版本不沿用舊的未核對摘要；核對未完成的結果不寫入摘要快取。核對使用生成時相同的官方摘錄範圍，不宣稱涵蓋完整條文；資料過長時會要求縮小範圍。

單則消息的 AI 分析也核對摘要、監理重點、分級理由、部門與流程影響、注意事項及建議。分級缺少理由或未獲支持時顯示「待確認」；不以規則建議補回被省略的 AI 內容。詳情頁可展開查看保留內容所對應的原文，並顯示未完成核對或省略原因。程式比對的條文差異、沿革修正條次另外標示，核對失敗仍保留這些來源事實。

單則分析生成與核對使用相同來源範圍，上限為 `AI_MAX_INPUT_CHARS` 與 5,000 字中的較小值；條文差異按完整條次選入，畫面提示節錄限制，完整比對仍可另行展開。未核對的舊分析快取不再沿用，核對未完成的結果不寫入快取；重新分析的核對失敗時保留前一份已核對結果，仍可手動重試。核對耗時記錄於 `generation_timing.review_seconds`。這項機制仍可能漏判，不能視為法律正確性保證。

三案例修正後，法規前後對照的分析上限另為 `AI_MAX_INPUT_CHARS` 與 8,000 字中的較小值。文字高度相似的新增／刪除條次會成組提供，提示可能移列，不據此認定法律效果相同；無法整組納入時不只提供其中一條。一般事件仍維持 5,000 字上限。事件與聚焦生成明確使用 16K 上下文，較長條文的生成等待上限為 180 秒；首次生成與核對可能需要更久。

部門使用既有標準職能分類；未知流程部門不再預設歸到法遵。系統提供原文作業詞彙對應的職能候選供模型參考，不直接當成 AI 結果發布。偵測到作業與諮詢／查核角色混淆、將文字異動擴張為新義務或草案條件不足時，最多用同一份來源進行一次聚焦的職能與建議生成，結果仍須接受來源核對。相關職能、流程與檢查建議均屬條件式初步推估，不代表公司已存在缺失或已確認正式權責。

來源核對區分事實、風險判讀、職能關聯及可選建議，不要求官方原文逐字列出合理的檢查方向。核對採小批次，限定回覆既有結論與原文片段編號；缺項或無效引用最多再核對一次，持續失敗仍不發布。草案另檢查建議是否越過準備階段，即使加上「若公司」也不能把「得辦理」改成必須執行的措施。這些是有限規則與模型判讀，不是完整法律語意驗證。

管理摘要與核對共用同一份來源快照，每筆上限 5,000 字，記錄全文／節錄範圍；能取得法規版本時，另提供修正／公布日，避免把資訊發布或收錄日當成修正日。長篇選取先分組生成與核對，再組合已核對內容，不另外推論跨組趨勢。主摘要因來源不支持而省略時，可依核對意見用同一來源重寫一次，仍未通過就提示資料不足。

另加入範圍有限的條件強度與條號對應規則，例如原文僅描述「經同意者」時，避免擴大成所有情形均須同意；避免僅因同一段出現條號與契約，就把兩者視為同一義務。這些規則只涵蓋可辨識的文字模式，不是完整法律邏輯推導。

可執行 `python scripts/evaluate_evidence_review.py --live`，以本機模型檢查七個合成正反例，涵蓋否定詞、例外、虛構流程、草案、條件強度及錯誤合計。結果獨立保存於 `tmp/evidence-review/live.json`，不寫入正式 AI 快取；少量案例不能推算實務法律問答正確率。

監理問答助手以「直接提問或描述工作 → Agent 理解問題及產生檢索詞 → 找相關官方段落 → 說明問題與法規的關聯 → 核對原文及適用條件」為共用流程。明確的法規問題可直接搜尋，不要求補充工作情境；所指事項無法辨識時才提出必要追問，補充後沿用前文。後續更正條件時以最新更正為準。同一問題最多六次輸入，新主題使用「開始新問題」清除前文。頁面提供直接問法規及客戶資料交付委外客服兩種提問範例，使用相同入口與流程。

共用檢索優先保存的完整官方法規原文，最多取四段，經引用檢查後按法規分組，顯示原文與 AI 整理的問題關聯。公告、裁罰、新聞及僅有沿革的資料另列為「其他官方資料」，避免冒充現行條文。找不到完整法規或必要條件尚不明時會說明缺口；不能僅憑搜尋結果保證適用、判定合法或虛構核准流程。每項關聯與建議均須引用已驗證的摘錄，憑空新增的條號會省略；引用存在仍不等於推論必然正確。

回答區依序顯示「回答」「待確認事項」「法規依據」。優先顯示現有且通過引用檢查的推論，沒有推論時顯示官方原文摘錄，不另外產生摘要。回答可連至對應法規；原文與版本、原問題與搜尋資訊預設收合，草案及引用檢查提醒保持可見。建議與資料缺口分開列出，手機維持同樣閱讀順序。

提問範例用來說明如何輸入，並非預先寫好的法律答案。回答依實際檢索與模型結果產生。提問、必要追問與補充條件只保留在目前頁面，重新整理或按「開始新問題」後清除；後端不另存問答。請勿輸入實際客戶個資或機密資料。

可用 `python scripts/evaluate_regulatory_qa.py` 執行五個固定的實際資料檢索案例，加入 `--live` 可量測目前本機模型的兩題回答及一題資料不足情境。腳本不寫入正式資料或分析快取，結果預設保存在 `tmp/qa/evaluation.json`；少量案例結果不代表整體正確率。

單一入口統一使用 `/api/regulatory-qa` 的 `mode: auto`，傳入 `history` 接續處理，回傳 `conversation` 包含問題理解、必要追問、建議與輸入次數。舊的 `question` 與 `scenario` API 模式保留相容性；前端已移除模式選單。先前的示範企業文件 API 保留相容性，但不作為此頁的入口或法規依據。

資料來源為主管機關公開資訊。公開公告、AI 分析、歷史資訊與法規版本可保存在本機 JSON 快取，這些執行資料已排除 Git。

公開法規版本保存於 regintel_law_versions_v1.json，記錄可取得的官方條文、實際修正／公布日期與來源，以支援監理資料更新流程。

修正前後對照會選取不晚於資訊發布日的兩個已取得官方版本，同日重抓不算另一版；有資料缺口時不推定為緊接前版。版本日期不是生效日期，附件、格式表與單純沿革不作為完整條文對照。缺少前版或無法解析條次時會顯示原因，不生成舊條文。初期可自動讀取保險法、保險代理人管理規則、保險經紀人管理規則及保險業招攬及核保理賠辦法的官方歷史頁；其他法規沿用本機已保存的版本。

一般 AI 分析只讀已保存版本，不會因新功能額外下載歷史頁。展開對照才讀取官方頁面，成功讀取後按法規修正版本快取一小時；取得差異後可按「依條文差異重新分析」。AI 輸入保留完整條文差異，超過上限時按整條節錄，未列條文不在該次 AI 分析範圍。可先執行 `python scripts/prepare_law_comparisons.py` 準備三部示範法規的真實官方版本。

AI 分析供初步參考；法律適用性、公告發布日與法規生效日仍須依官方原文核對。來源讀取或內容不足時，依畫面提示確認官方資訊。

首次資料載入失敗時，清單與詳情會結束載入狀態，顯示失敗原因及「重新載入」入口；更新失敗時則保留上次資料與詳情。維護診斷保留在瀏覽器主控台。

可用 `node scripts/verify_platform_browser.cjs --live-qa` 執行獨立瀏覽器檢查。需要 Playwright 與已安裝的 Chrome；Python 可用 `REGINTEL_VERIFY_PYTHON` 指定。腳本以保存的公開資料啟動獨立測試服務，檢查失敗重試、搜尋與分頁、篩選同步及摘要選取；`--live-qa` 另以目前本機模型完成一題實際問答。AI 分析更新及摘要狀態使用受控回覆，沒有重新評估其法律內容；測試不更新正式快取，服務會在結束時停止。詳細範圍及本次結果見 [2026-10-22 檢查報告](docs/platform-verification-2026-10-22.md)。
