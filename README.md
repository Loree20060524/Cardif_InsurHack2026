# RegIntel — 保險業監理情報與風險預警平台

整合官方公告、法規、裁罰與監理新聞，以本機 Ollama 提供 AI 重點分析與使用者選取資訊的管理摘要。

## 主要功能

- **監理資訊**：依資訊類型瀏覽官方資料，搜尋公告與法規；可依主要責任部門、風險程度及重要性篩選。
- **資訊分頁**：每頁可顯示 25、50 或 100 筆，支援上一頁、下一頁及選取頁碼；可載入更早的官方資料。
- **AI 分析**：整理重點、可能受影響部門與流程、需要注意的事項及建議因應，附上官方來源連結。
- **管理摘要**：使用者自行勾選要納入的資訊，跨頁、搜尋及切換類型會保留選取；摘要使用生成時選取的資料。
- **AI 監理問答**：搜尋已收錄的官方資料，依原文段落回答問題；區分官方原文重點與 AI 推論，提供可展開的引用依據、資料類型與日期篩選。
- **修正前後對照**：法規詳情預設收合，逐條顯示新增、修正及刪除文字、版本日期和官方來源。異動摘要由程式產生；部門影響與因應建議標示為 AI 推論。
- **來源狀態**：查看各官方來源的更新情況。

公司作業檢查、SOP 上傳及文件比對已移除。平台目前以公開監理資料為分析範圍，沒有公司文件上傳入口；舊的文件解析、比對及私有摘要 API 回傳 HTTP 410。

## 啟動

預設使用本機 Ollama 與 qwen3:4b：

```powershell
ollama pull qwen3:4b
python -m pip install -r requirements.txt
python server.py
```

瀏覽器：

```text
http://127.0.0.1:8082
```

目前版本為 **RegIntel v10.20**。更新後，先在原本執行服務的視窗按 Ctrl+C，再執行此資料夾的 server.py；瀏覽器按 Ctrl＋F5 載入新版頁面。

若啟動時提示連接埠已有服務，請直接開啟原本的網址，或先停止舊程序再重新啟動。

Vercel 的 Python 入口與靜態建置設定已備妥；**持久化資料庫與雲端 AI 尚未接妥，目前不是完整上線版**。設定與驗證狀態見 [Vercel 部署準備](docs/vercel-deployment.md)。

其他 Python 主機可設定 `REGINTEL_HOST=0.0.0.0`、主機提供的 `PORT`，以及指向持久化磁碟的 `REGINTEL_DATA_DIR`。本機預設位置不變，詳見 [一般雲端部署設定](docs/cloud-deployment.md)。

### 模型與附件

- 本機 AI 使用 Ollama；預設 API 位址為 http://127.0.0.1:11434/api/chat。
- 為降低等待時間，分析預設使用 `think: false`，保留原本的模型、來源內容與輸出欄位；啟動服務後會在背景預載已安裝模型。
- 無法使用本機 AI 時，公開監理資訊可使用原本的規則備援，畫面依實際分析狀態顯示。
- pypdf 用於官方公告的可讀 PDF 附件，不提供使用者文件上傳。

### 分析速度與設定

`OLLAMA_THINK` 可設定為 `false`（預設）、`true`（開啟 thinking）或 `auto`（沿用模型預設）。單筆分析及管理摘要使用同一設定；不同設定的分析快取分開保存。模型在記憶體中的保留時間由 `OLLAMA_KEEP_ALIVE` 控制，預設 `10m`。修改環境變數後需重新啟動服務。

若要恢復模型原本的 thinking 設定：

```powershell
$env:OLLAMA_THINK = "auto"
python server.py
```

新增分析結果的 `generation_timing` 記錄來源讀取、模型載入、輸入處理、文字生成與整體耗時；取用快取時，這些數值描述原分析的生成時間。

詳情頁的「重新分析」會略過既有分析快取、重新呼叫模型；一般瀏覽仍沿用快取。分析進行中不接受同一事件的重複請求，重跑失敗時會標示狀態並保留原結果。

可使用不寫入正式快取的腳本比較速度：

```powershell
python scripts/benchmark_analysis.py --modes default off --output tmp/performance/comparison.json
```

腳本只連接本機已安裝的 Ollama 模型，預設使用目前本機快取的一筆公開裁罰資料。可用 `--event` 指定資訊 ID，`--summary` 檢查管理摘要，或 `--modes configured` 驗證目前設定。速度與分析品質仍須依實際來源抽樣確認；首筆分析另包含模型載入成本。

## 資料與結果

監理問答第一版使用中文詞片、常用詞對應與 BM25 排序，沿用目前的 Ollama 模型，不需下載向量模型。搜尋範圍包含本機已保存且符合平台相關性條件的公告、裁罰、新聞及法規原文；每部法規原文使用平台保存的最新版本。來源更新後會重建記憶體中的搜尋索引，不會在提問時抓取外部網站。日期篩選使用發布或修正／公布日，不能作為法規生效期間查詢；沒有完整歷史版本時，也不能據此判定過去某日的適用規範。

每項回答必須引用實際搜尋到的段落，後端檢查來源編號與逐字摘錄，未通過的回答會省略。官方事實直接顯示通過檢查的原文摘錄，避免小模型改寫時反轉例外條件；AI 推論另行標示。這項檢查不等於驗證結論正確，仍須核對摘錄是否支持問題或推論。沒有相關段落時不呼叫模型，直接提示資料不足；模型無法使用時會提示重試，不會把規則結果冒充 AI 回答。第一版每次處理一個獨立問題，重新整理頁面後不保留問答內容。

可用 `python scripts/evaluate_regulatory_qa.py` 執行五個固定的實際資料檢索案例，加入 `--live` 可量測目前本機模型的兩題回答及一題資料不足情境。腳本不寫入正式資料或分析快取，結果預設保存在 `tmp/qa/evaluation.json`；少量案例結果不代表整體正確率。

資料來源為主管機關公開資訊。公開公告、AI 分析、歷史資訊與法規版本可保存在本機 JSON 快取，這些執行資料已排除 Git。

公開法規版本保存於 regintel_law_versions_v1.json，記錄可取得的官方條文、實際修正／公布日期與來源，以支援監理資料更新流程。

修正前後對照會選取不晚於資訊發布日的兩個已取得官方版本，同日重抓不算另一版；有資料缺口時不推定為緊接前版。版本日期不是生效日期，附件、格式表與單純沿革不作為完整條文對照。缺少前版或無法解析條次時會顯示原因，不生成舊條文。初期可自動讀取保險法、保險代理人管理規則、保險經紀人管理規則及保險業招攬及核保理賠辦法的官方歷史頁；其他法規沿用本機已保存的版本。

一般 AI 分析只讀已保存版本，不會因新功能額外下載歷史頁。展開對照才讀取官方頁面，成功讀取後按法規修正版本快取一小時；取得差異後可按「依條文差異重新分析」。AI 輸入保留完整條文差異，超過上限時按整條節錄，未列條文不在該次 AI 分析範圍。可先執行 `python scripts/prepare_law_comparisons.py` 準備三部示範法規的真實官方版本。

AI 分析供初步參考；法律適用性、公告發布日與法規生效日仍須依官方原文核對。來源讀取或內容不足時，依畫面提示確認官方資訊。

## 程式碼分層

```text
index.html                              頁面結構
assets/css/                             各畫面區域樣式
assets/js/core.js                       共用狀態與工具
assets/js/app.js                        視圖切換與啟動
assets/js/pagination.js                 分頁與歷史資料載入
assets/js/detail-view.js                資訊詳細頁
assets/js/management.js                 資訊選取與管理摘要
server.py                               啟動入口
regintel/config.py                      環境與檔案設定
regintel/domain/                        分類、文字工具與風險規則
regintel/infrastructure/                官方資料、附件、JSON 與 Ollama
regintel/infrastructure/law_versions.py  公開法規版本保存與 XML 收錄
regintel/application/                   更新流程、資訊分析與管理摘要
regintel/web.py                         HTTP 路由與伺服器啟動
```
